# DI-1001 保险须知逐项阅读与确认设计

**日期**：2026-10-27  
**范围**：DataInsights 本地保险产品录制与回放 Demo  
**状态**：用户已确认交互方向，书面规格待最终复核

## 1. 背景与目标

保险投保页面通常要求用户查看并确认多份须知、条款和授权文件。当前本地 Demo 只有录制告知、保障详情和投保表单，无法验证多份文件逐项打开、长内容滚动、确认状态变化以及提交门禁的录制与回放效果。

本变更在去生产化保险 Demo 中增加一套强制逐项阅读流程，用真实 rrweb 事件验证复杂保险交互。它只扩展本地验证页面，不改变 DataInsights SDK 公共 API、录制协议或 rrweb 核心。

## 2. 范围

### 2.1 纳入范围

- 在投保表单提交区前展示五份模拟保险文件；
- 每份文件通过底部阅读弹层打开；
- 正文滚动到底后才允许确认；
- 展示逐项确认状态、确认顺序和剩余数量；
- 全部确认前禁止提交投保表单；
- 全部确认后生成脱敏的业务自定义事件；
- 使用真实浏览器 E2E 验证录制、回放和密码保护不回归。

### 2.2 排除范围

- 不接入真实保险条款、生产接口或电子签名；
- 不下载或保存 PDF；
- 不验证条款的法律效力；
- 不修改 SDK 授权语义；
- 不新增后端、数据库或正式回放控制台能力。

## 3. 文件与展示顺序

页面固定展示以下五项去生产化模拟文件：

1. 投保须知；
2. 保险条款；
3. 健康告知；
4. 免责条款；
5. 个人信息处理授权书。

每项具有稳定的内部文档代码和版本，但界面只展示业务名称、简短说明及“待阅读/已确认”状态。模拟正文不得复制生产保险条款，也不得包含真实个人信息、生产 URL、Cookie、Token 或监控脚本。

## 4. 交互设计

### 4.1 打开与阅读

- 点击文件行打开底部弹层；
- 弹层包含文件标题、版本、长正文、关闭按钮和确认按钮；
- 每次打开时正文回到顶部；
- 正文区域独立滚动，页面底层不随之滚动；
- 只有正文已经到达底部，确认按钮才从禁用变为可用；
- 内容无需滚动即可完整显示时，按钮直接可用，以避免不可完成状态。

### 4.2 确认状态

- 点击“我已阅读并确认”后关闭弹层；
- 对应文件显示“已确认”和确认次序；
- 重复打开已确认文件可以再次阅读，但不会重复增加确认次数或改变首次确认顺序；
- 关闭弹层、按关闭按钮退出或未滚动到底退出均不得确认；
- 状态仅保存在当前页面内存中；页面刷新后重新确认，符合本地 Demo 的可重复验证目标。

### 4.3 提交门禁

- 未完成全部五项时，`#submit-policy` 保持禁用；
- 模块显示“还需确认 N 项”；
- 全部确认后按钮启用并显示“已完成全部阅读确认”；
- 原生表单提交处理再次检查完成状态，避免仅通过 DOM 修改绕过 Demo 门禁；
- 门禁失败不调用 `DataInsights.stop()`，也不显示投保成功状态。

## 5. 录制数据设计

普通点击、弹层 DOM 变化、正文滚动、按钮状态和确认标识由 rrweb 原生事件记录。完成全部确认时调用：

```js
DataInsights.addCustomEvent('insurance-notices-confirmed', {
  noticeVersion: 'local-insurance-notices-v1',
  documentCodes: [
    'application-notice',
    'policy-terms',
    'health-disclosure',
    'exemption-clauses',
    'privacy-authorization',
  ],
  confirmationOrder,
});
```

自定义事件不得包含完整条款正文、用户输入、姓名、手机、证件号、密码或确认时间戳。事件时间戳由 SDK 自身记录；页面状态中可展示本地确认顺序，但不依赖客户端时间作为法律证据。

## 6. 组件与文件边界

- `examples/insurance-product/index.html`：须知列表和单个共享阅读弹层；
- `examples/insurance-product/styles.css`：列表、状态、长文本滚动区和移动端弹层样式；
- `examples/insurance-product/app.js`：文档数据、打开/关闭、到底检测、幂等确认、提交门禁和自定义事件；
- `test/insurance-product.e2e.test.ts`：真实浏览器录制、提交门禁、确认过程和回放断言。

使用一个共享弹层渲染五份文档，避免重复 DOM 和重复监听器。文档代码只来自页面内固定配置，不读取 URL 或外部响应。

## 7. 异常与可访问性

- 找不到必需 DOM 时，Demo 初始化应安全失败并在测试中暴露，不影响 SDK 自身错误边界；
- 弹层使用 `role="dialog"`、`aria-modal="true"` 和标题关联；
- 状态变化使用可读文本，不能只依赖颜色；
- 按钮使用原生 `disabled`；文件入口使用原生 `button`；
- 关闭后焦点返回刚才打开文件的按钮；
- 所有事件监听只安装一次，不修改 rrweb 配置。

## 8. 测试与验收

E2E 必须先以缺少功能的状态失败，再实现页面行为。测试至少验证：

1. 页面存在五份文件，初始全部待确认且提交按钮禁用；
2. 打开文件后，未滚动到底不能确认；
3. 滚动到底后确认按钮启用；
4. 关闭未确认文件不改变状态；
5. 可以按非固定顺序完成五项，确认次序被正确记录；
6. 重复确认不产生重复项；
7. 全部确认后提交按钮启用，自定义事件只出现一次；
8. 录制数据包含须知名称、确认状态和滚动/点击过程；
9. 录制数据不包含密码值，且自定义事件不包含文件正文或用户字段；
10. 回放最终状态显示五项已确认并能成功提交；
11. 现有 `0.75x/1x/2x/4x/8x`、进度条、`skipInactive=false` 和沙箱回放断言保持通过；
12. 所有非本地 HTTP(S) 请求仍被拒绝。

- SDK 全量测试、类型检查和构建通过；

- 本地页面可以直观看到并回放逐项阅读确认全过程。
