# DI-1001 众安页面高保真模拟与真实输入时间轴设计

## 目标

将 DataInsights 本地保险演示页升级为指定众安公开产品页的高保真、完全本地化测试镜像，并让 1x 回放真实保留用户逐字输入和操作停顿。

参考页面：

`https://m.zhongan.com/gp/99440765?cid=10002542174&templateType=MSZQNJ&bizOrigin=LY_MSZQ_promoCode0000700009&activityCode=ZAlifeMSZQ&promoCode=0000700009`

## 范围与边界

本地镜像用于 SDK 录制与回放测试，不提供真实投保、核保、支付、登录或众安后台连接。页面应明确显示“DataInsights 本地测试镜像”，避免被误认为生产保险页面。

允许将参考页公开图片下载到仓库并从 `127.0.0.1` 提供。不得复制或运行参考页的生产 JavaScript，不得调用众安业务 API、埋点、风控、监控或支付接口。

## 方案决策

采用方案 A：rrweb 输入采样从 `input: 'last'` 调整为 `input: 'all'`，使非密码输入框的每次实际变化都带原始时间戳进入事件流。播放器默认 `skipInactive: false`，1x 使用完整事件时间线；2x、4x、8x 才改变播放速率。用户仍可手动开启“跳过静止”。

该方案优先保证保险销售可回溯场景的行为真实性。增加的输入事件量通过既有批量、Journal、Outbox 和分层上送机制处理，不通过合成动画伪造用户操作。

## 页面内容

本地页面按移动端 390px 基准还原以下内容：

- 惠选版、优享版双方案切换；
- 保障内容清单、金额、等待期、免赔额和赔付比例；
- 起始价格与“立即投保”固定操作区；
- “为什么要购买医疗险”说明；
- 高保额、免健康告知、理赔便捷、52 种特药、优质医疗服务图文模块；
- 理赔流程；
- 常见问题折叠面板；
- 保险公司、产品说明和风险提示；
- 本人信息、为谁投保、保费支付等本地模拟表单。

页面不要求逐像素复制由生产数据动态决定的内容，但模块顺序、主视觉、色彩、间距、字体层级、固定底栏和主要交互应与参考页面一致。

## 交互设计

- 方案标签切换时更新保障内容、价格和选中状态；
- “保障详情”打开本地抽屉或弹层；
- 页面导航滚动到投保、产品特色和理赔说明；
- FAQ 支持单项展开与收起；
- 产品页面加载完成后立即显示阻断式录制告知弹层并遮罩页面；
- 告知弹层仅提供“同意并继续”，未同意时不能操作产品页，可通过浏览器返回离开；
- 点击“同意并继续”后才由嵌入方授予录制授权、启动 SDK，并生成首个全量快照；
- 告知弹层及用户同意前的点击、滚动和 DOM 状态不进入录制内容；
- 点击产品页“立即投保”只进入本地投保表单，不再承担录制授权语义；
- 投保表单支持姓名、手机号、证件号、出生日期、关系、社保状态、保额和支付周期等本地字段；
- 提交时等待 `DataInsights.stop('completed')` 成功后才显示完成状态。

## 录制告知

告知弹层视觉参考用户提供的保险页面：背景整体变暗，底部白色圆角面板包含品牌区、醒目标题、用途说明和橙色主按钮。文案必须说明这是 DataInsights 本地测试镜像，并明确“投保过程操作、页面行为将被记录留存，用于销售可回溯、纠纷核验”。

告知版本使用稳定的 `noticeVersion`。同意动作、版本和时间作为 SDK consent evidence 保存。刷新页面视为新的访问，重新显示告知并重新取得本次访问授权，不使用持久化状态绕过弹层。

## 录制与隐私

- 普通文本、选择、单选和数值字段记录每次变化及其真实时间戳；
- `type=password` 继续强制掩盖，不得在事件、Journal、Outbox、请求体或回放 DOM 中出现明文；
- `rr-sensitive` 区域继续按 SDK 脱敏规则处理；
- 页面在用户点击“同意并继续”之前不启动行为录制；
- SDK 不向 Spec、SGS、OpenSpec 或其他分析服务上报任何信息。

## 回放时间语义

- `1x + skipInactive=false`：事件间隔与录制时间戳差值一致；
- `1x + skipInactive=true`：仅在用户主动打开后跳过长静止区间；
- `2x/4x/8x`：在所选倍速下缩短时间；
- 输入内容按真实输入事件逐步出现，不允许一次性注入最终值；
- 进度条总时长以首个和最后一个有效 rrweb 事件的时间戳差值为准。

## 错误处理

- 本地图片缺失时显示固定尺寸占位块，避免布局塌陷；
- SDK 初始化失败时页面仍可浏览，但投保入口显示录制不可用；
- 录制收尾失败时不得显示投保完成，允许用户重试；
- 回放数据缺段时显示完整性警告，不以加速或补帧掩盖缺口。

## 验收与测试

浏览器验收测试必须覆盖：

1. 页面关键模块、方案标签、图文区、理赔流程、FAQ 和固定底栏可见；
2. 所有图片、脚本、样式和接口请求均为本地地址；
3. 方案切换、详情、FAQ、导航和表单交互正常；
4. 初次打开时告知弹层阻断页面，未同意前录制列表为空；
5. 点击“同意并继续”后弹层消失，录制启动且首个全量快照不含告知弹层；
6. 输入一个至少 4 个字符的姓名时，事件流包含多次递增的 input 事件而非单个最终值；
7. 在两次输入之间保留可控停顿，事件时间戳差值符合录制等待时间；
8. `skipInactive=false` 的 1x 回放时，进度条总时长与事件时间跨度一致，并能观察到逐字输入；
9. 开启 `skipInactive` 后才允许缩短长停顿；
10. 密码明文在存储、传输和回放中均不存在；
11. 既有 Journal、Outbox、分段回放和 SDK 全量测试继续通过。

## 非目标

- 不克隆众安生产 React 应用或其私有接口；
- 不模拟真实保费计算、风控、核保、签约、支付或出单；
- 不把本地测试镜像发布为可对外访问的产品页面；
- 不保证参考页面未来变化后自动同步，本次资源以实施时抓取版本为基线。
